virtio-net 与 SR-IOV 各管哪一层？沿着一张网卡看发包路径

Published2026-11-27|Updated2026-11-27|虚拟化

在虚拟机里看到网卡使用 virtio_net 驱动，能据此判断宿主 CPU 会处理每个包吗？NVIDIA BlueField 提供了一个值得对照的例子。它可以把一个 PCIe VF 分给虚拟机，而 guest 加载的恰好就是 virtio_net。NVIDIA BlueField Virtio-net 手册，第 21 页

virtio 定义驱动与设备之间的编程接口，SR-IOV 定义 PCIe 设备如何暴露多个可分配的功能。 从一块网卡的两个问题入手，就能看清各自的职责。

问题 哪项技术回答 网卡上的具体含义
Guest 已经看到一张网卡，驱动怎样让它发包？ virtio-net 驱动和设备协商特性，驱动通过发送队列提交缓冲区，设备用完成信息告知驱动哪些缓冲区可以回收。Linux virtio 文档
宿主机只有一张物理网卡，怎样让多台 VM 各自得到可分配的 PCIe 功能？ SR-IOV 宿主机通过物理功能（PF）启用多个虚拟功能（VF）。每个 VF 有自己的 PCIe 标识、配置空间和可供驱动操作的寄存器。Linux PCI SR-IOV 文档

图中最值得看的是 virtio-net 指向 VF 的那条线。在 BlueField 的 virtio-net 实现里，静态 virtio-net PF 支持通过 SR-IOV 暴露 VF，每个这样的 VF 都能作为一个独立的 virtio-net PCIe 设备分配给 guest。同一张网卡，在 PCIe 这一层是 VF，在驱动接口这一层是 virtio-net。 因此，看到 virtio_net 驱动，只能确定 guest 使用什么接口。要判断宿主 CPU 是否参与逐包处理，还得看谁消费发送队列。NVIDIA BlueField Virtio-net 手册，第 19–21 页

图二：同一个 TCP 包的两条发送路径

工程上说“选 virtio 还是 SR-IOV”，通常是在比较两种具体部署。假设同一台 VM 配有两张网卡，应用往节点外发送数据，guest 根据路由选择一张出口网卡。图左采用 virtio-net + vhost-net 软件后端，图右采用厂商 VF + PCIe 直通。两路都从 guest 的 TCP/IP 栈开始，最终共用一个物理端口。Red Hat 虚拟化调优指南，网络章节

同一个 TCP 包，两种发送队列 · 分步图解
  1. 软件路径：提交 virtqueue。先沿上排走一遍。guest 驱动把指向包数据的描述符放入发送队列，由已配置的 vhost-net 取出。
  2. 软件路径：从后端到物理端口。本例使用 TAP 和 Linux 网桥；宿主网络栈及驱动把流量交给物理网卡。上排的队列由宿主软件消费。
  3. 直通路径：提交 VF 描述符。再走下排。guest 里的厂商驱动按设备格式填写队列并通知 VF。设备分配和 DMA 映射已由宿主事先建立。
  4. 直通路径：由网卡发送。硬件读取授权缓冲并从物理端口发出。图中两个案例的包均抵达外网，消费 guest 发送队列的部件却在不同位置。

左路由宿主侧软件消费发送队列。 virtio_net 把描述符提交到发送 virtqueue。描述符告诉后端待发送数据在哪块内存、有多长。本例由宿主内核里的 vhost-net 取出请求，再经 TAP、Linux 网桥和宿主网卡驱动发出去。QEMU 负责创建设备、配置后端。启用 vhost-net 后，常规发送路径可以留在内核里，无需每个包都回到 QEMU 用户态。Linux virtqueue 文档 · Red Hat 虚拟化调优指南

右路由分配给 VM 的网卡硬件消费发送队列。 宿主机先通过 PF 启用 VF，再由 QEMU 配合 VFIO 把某个 VF 分给 VM。Guest 的 VF 驱动按网卡规定的格式填写发送描述符，通知设备有新请求。网卡随后通过 DMA 读取描述符和包数据。这条直通路径可以绕过宿主机的 TAP、软件网桥和宿主网卡驱动的逐包处理。宿主机仍负责设备分配、建立 DMA 映射，IOMMU 按映射限制设备可以访问的内存。Linux PCI SR-IOV 文档 · Linux VFIO 文档

放到训练平台里，区别落在哪里？

对调度器，区别是要分配什么资源。 普通软件 virtio 网卡无需消耗物理网卡的 VF。申请一个直通 VF，则要求目标节点恰好有兼容且空闲的 VF。图二里，即使 VF 各自有独立的 PCIe 标识，所有从同一物理端口发出的流量仍要分享链路带宽。Linux PCI SR-IOV 文档

对训练进程，区别是能调用什么接口。 普通 virtio-net 提供以太网收发能力。若训练进程要在 VM 内创建 RDMA 队列对（QP），并使用硬件 RoCE，guest 还得看到支持 RDMA 的设备。一种常见做法是给 VM 分配支持 RoCE 的 VF，并加载配套的 RDMA 驱动。看到一张 VF 时，仍需要确认这款设备和当前配置向 guest 暴露了哪些能力。NVIDIA 对 VF 与 RoCE 的说明

读架构图时，可以沿着一张网卡依次问三个问题：它从哪里分出来？Guest 用什么驱动操作它？最终是谁消费发送队列？

部署 网卡从哪里来 Guest 使用的驱动 谁消费 guest 的发送队列
软件 virtio-net（图二左路） QEMU 创建虚拟网卡 virtio_net 宿主内核的 vhost-net
厂商 VF 直通（图二右路） PF 通过 SR-IOV 暴露 VF 厂商 VF 驱动 网卡硬件
BlueField virtio-net VF 静态 virtio-net PF 通过 SR-IOV 暴露 VF virtio_net BlueField 的设备数据路径

两种 VF 都由 PF 暴露，guest 却可能加载不同的驱动。同一个 virtio_net 驱动也可以对接不同的后端。做平台选型时，分别写下要分配的资源、guest 可见的接口、承担逐包处理的部件，这三种部署的差别就清楚了。
